III.1

A* Pathfinding Algorithm

The algorithm that finds the shortest path is called A* (A-star). It works like a smart frontier search: it always expands the cell that looks most promising — cheapest so far, plus a guess of how far remains. The guess is the straight-line distance to the goal. Because straight-line distance never overestimates real distance, A* is guaranteed to find the true shortest path.

This distance-only path is the baseline. In the sections that follow, terrain costs are layered on top, and the path bends in response. Every deviation you see is caused by friction that did not exist here.

// Step cost: how far is one move?
//   straight step (N/S/E/W) → 1.0
//   diagonal step           → 1.4
//   knight-move step        → 2.2

// --- Setup ---
mark every cell as unvisited, best_cost_to = ∞
best_cost_to[start] = 0
add start to frontier  // frontier = cells to explore, sorted by priority

// --- Search ---
while frontier not empty:
  current = pick cell with lowest priority from frontier
  if current == goal: stop   // reached destination

  for each neighbour of current:
    cost_so_far  = best_cost_to[current] + step_cost   // actual distance walked
    straight_line_to_goal = sqrt( row_gap² + col_gap² ) // best-case remaining
    priority     = cost_so_far + straight_line_to_goal   // lower = more promising

    if cost_so_far < best_cost_to[neighbour]:
      best_cost_to[neighbour] = cost_so_far
      came_from[neighbour]    = current   // remember how we got here
      add neighbour to frontier with this priority

// --- Reconstruct path ---
// follow came_from[] backwards from goal to start
III.2

Elevation-Change Cost

Slope as resistance: routes bend toward valleys, saddles, and gentle grades.

Terrain is not flat. Ascending a slope costs energy; descending costs control and safety. Once elevation change enters the cost function, routes bend away from mountains and towards valleys, saddles, and river plains — the same topographic logic that placed Rome's roads along the gentle gradients between her hills.

Uphill and downhill costs need not be equal. A laden mule exhausts itself climbing; it merely risks a stumble going down. Early road builders intuitively calibrated these asymmetries, choosing routes that traded extra distance for manageable grades. The Via Appia holds a consistent 3–4% grade for hundreds of kilometres precisely because that is the threshold of cart viability.

A maximum slope parameter makes steep terrain simply impassable — the algorithmic equivalent of a cliff. Routes are forced through passes, creating the bottlenecks that mountain communities have exploited for taxation and defence across history.

Adjust the sliders and watch the elevation path retreat from steep ridges, converge on passes, and trace the valley floors. The blue distance path holds its straight line; the red elevation path bends wherever the terrain demands.

// Elevation-weighted edge cost
function edgeCost(i, d):
  dist   = DD16[d] × UNIT_M     // ground distance in metres
  dElev  = elev[nbr] - elev[i]   // positive = uphill
  slope  = |dElev| / dist

  if slope > maxSlope: return ∞   // impassable

  cost = dist
  if dElev > 0:  cost += uphill   × dElev
  else:          cost += downhill × |dElev|

  return cost

III.3

Modes of Transportation

Each technology defines its own cost surface across the landscape.

Not all travellers are equal before the same slope. A pedestrian scrambles over terrain that would halt a loaded cart; a boat glides where every other mode stalls. Each technology defines its own cost surface across the landscape, and the paths that emerge from each surface are distinct.

Roman roads were engineered for the cart — broad, graded, paved — tolerating no more than about 8–10% grade. Mule tracks wound steeper. Aqueducts demanded near-perfect level. Waterways ignored slope entirely, paying instead in portage at every watershed divide.

The parameters are not arbitrary. Pedestrians maintain efficient walking up to about 15–20% grade. Laden mules begin to struggle beyond 25%. Wheeled vehicles on unpaved surfaces rarely manage more than 10%. Below these thresholds, the extra energy cost of climbing is the dominant variable; above them, travel simply stops. These limits hardwired themselves into landscape at every scale.

Place two pins and compare all three routes simultaneously. Pedestrian paths cut directly across ridges; mule tracks find compromise; cart and watercraft routes flatten out in valleys and rivers, avoiding steep land entirely.

III.4

Intermodal Pathfinding

The cost of switching modes — dock, warehouse, portage — concentrates crossings into natural terminals.

No single mode dominates every environment. The most efficient journeys in pre-industrial Rome combined boat along the Tiber, cart along the Via Appia, and foot for the last mile into the hills. But changing modes is expensive: cargo must be unloaded, repacked, transferred, and reloaded. Animals must be exchanged. Vessels must find harbour.

Each modal transition carries a fixed penalty that represents this friction — the toll of the warehouse, the wait at the dock, the cost of the carter's guild. When that penalty is low, routes fragment into many short modal segments; when high, travellers commit to a single mode for the whole journey even at the cost of efficiency in hostile terrain.

The result is spatial concentration: crossings do not distribute evenly along a shoreline but cluster at the few points where the combined cost (transition + approach + departure) is minimised. These clusters are the embryo of a port, a bridge town, a caravanserai. Geography proposes; transaction cost selects.

Red cells in the simulation mark where crossings concentrate — watch them sharpen into a handful of persistent terminals as travels accumulate. Lower the shore penalty and watch them dissolve back into the shoreline.

// Intermodal edge cost
step_cost = straight_distance   // 1.0 / 1.4 / 2.2

if both cells are water:
  step_cost ×= waterFactor        // water travel speed
else if both cells are land:
  step_cost += uphill   × rise × step_cost
  step_cost += downhill × drop × step_cost

if one cell is land, other is water:
  step_cost += shore_penalty       // cost of switching mode
III.5

Path Dependency

Use reduces cost. From tracks to roads to corridors — the self-reinforcing emergence of a network.

A path used once is easier to use again. Vegetation is trampled; the surface compacts; the route becomes known. With investment, a track becomes a road: graded, drained, paved. Each improvement further concentrates traffic, which justifies further improvement. The result is a self-reinforcing network — a small number of dominant corridors emerge from what began as a uniform probability field of possible paths.

This is path dependency in its spatial form: the cost of movement through an edge decreases as a function of how many times it has been traversed. The reduction is multiplicative and asymptotic — a well-worn road eventually costs half what a virgin path does for movement, and the transition penalty (boarding a boat, crossing a ford) decays toward zero as a dock or bridge is established.

The shape of the decay curve determines whether the network consolidates quickly into a few highways or spreads evenly. The formula used here — 0.5 + 0.5^(tc+1) — reaches 75% of original cost after one use, 63% after two, approaching 50% asymptotically. This matches observed empirical road formation dynamics.

The two simulations below run simultaneously with the same parameters and the same random travellers. The left runs without path dependency — pure terrain cost every time. The right accumulates use: edges traversed more often become cheaper, and the network self-organises into corridors. The contrast shows how much of a road network is topography, and how much is accumulated history.

// How path dependency reduces cost over time
times_used = how many travellers have crossed this edge

reduction_factor = 0.5 + 0.5 ^ (times_used + 1)
// times_used = 0  →  factor 1.00  (virgin ground, full cost)
// times_used = 1  →  factor 0.75  (worn track)
// times_used = 3  →  factor 0.56  (established path)
// times_used → ∞  →  factor 0.50  (paved road, half cost)

effective_cost = terrain_cost × reduction_factor

// Shore crossings also wear in — a ford becomes a bridge:
shore_cost = shore_penalty × 0.5 ^ times_used
