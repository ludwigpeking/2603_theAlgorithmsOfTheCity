Algorithms of the City Introduction

Introduction

This project describes the processes that shape cities as algorithms, and runs them as simulations, one layer at a time.

0.1

Premise

Cities are usually discussed as products of planning and design. Most of their form, however, comes from many separate decisions made over a long time: where to settle, which route to take, where to trade, what to claim, what to defend. Each decision follows a fairly simple rule, and each changes the conditions for the next.

Cities with no shared designer often arrive at similar forms, because they face similar pressures. That regularity suggests the rules can be stated explicitly. This project tries to state them precisely enough to be executed.

0.2

Relation to the Earlier Book

The ideas come from An Evolutionary History of the City, a series of lectures that treats the city as an evolutionary, self-organising system, and as the hardware of three kinds of organisation: security, economy, and ideology.

The book argues through history and examples. This project restates the same arguments as algorithms and tests them in simulation. The table shows roughly which book chapters each chapter here draws on.

0.3

What "Algorithm" Means Here

Each algorithm has three parts: an objective (what an agent is trying to achieve), constraints (the limits it acts under), and a decision rule (how it chooses). Many algorithms run at the same time, and each one alters the state the others work on. A path that is used becomes cheaper to use again, so early outcomes affect later ones.

repeat each time step:
    for each algorithm:                              // in no fixed order
        for each agent:
            options   = feasibleActions(agent, cityState, constraints)
            decision  = best(options, objective)
            cityState = apply(decision, cityState)
0.4

How the Chapters Are Organised

The chapters follow a rough historical order, from resources and settlement to paths, trade, claims, and defence. In practice the layers overlap, so each chapter is self-contained and can be read on its own.

Each entry has a short explanation, a pseudocode block for the key algorithm, and a simulation with adjustable parameters. The chapters share one simulation core and, where terrain matters, the same map of Rome and Lazio; they differ in the parameters and in the layer they add.

The project is open. Corrections and new chapters are welcome through the repository.
