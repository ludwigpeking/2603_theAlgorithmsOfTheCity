III · Pathfindings

Movement through space is never free. Every path is a negotiation between the traveller's goal and the resistance of the terrain — distance, slope, water, prior use. This chapter traces how those constraints have shaped the routes cities grow along, from the first shepherd's shortcut to the rail corridor.

III.1

Distance-Based Pathfinding

The simplest account of movement is pure distance: a traveller chooses the route that minimises total ground covered, treating every step as equal regardless of what lies underfoot. This is the straight-line instinct — the crow's path — and it remains a useful baseline against which every real friction is measured.

In practice, pure distance paths follow ridges and cross rivers wherever they happen to be shortest. They ignore the cost of climbing, the danger of water, and the benefit of worn tracks. Yet the heuristic is not idle: in open flat terrain with no barriers it produces exactly the paths people take.

The simulation here sets all terrain penalties to zero. Only cell-to-cell Euclidean distance drives the cost. Watch how routes cut straight across hills and wade through rivers without hesitation.

// Distance-only A*
function edgeCost(i, d):
  dist  = DD16[d]          // 1, √2, or √5 cell-lengths
  return dist              // nothing else matters

function heuristic(a, b):
  return euclidean(a, b)   // admissible: never overestimates

III.2

Elevation-Change Cost

Terrain is not flat. Ascending a slope costs energy; descending costs control and safety. Once elevation change enters the cost function, routes bend away from mountains and towards valleys, saddles, and river plains — the same topographic logic that placed Rome's roads along the gentle gradients between her hills.

Uphill and downhill costs need not be equal. A laden mule exhausts itself climbing; it merely risks a stumble going down. Early road builders intuitively calibrated these asymmetries, choosing routes that traded extra distance for manageable grades.

Adjust the uphill and downhill penalties and watch the paths retreat from steep slopes and converge on passes and valley floors.

// Elevation-weighted edge cost
function edgeCost(i, d):
  dist   = DD16[d] * UNIT_M        // metres
  dElev  = elev[nbr] - elev[i]

  if dElev > 0:
    cost = dist + uphill   * dElev
  else:
    cost = dist + downhill * |dElev|

  return cost

III.3

Modes of Transportation

Not all travellers are equal before the same slope. A pedestrian scrambles over terrain that would halt a loaded cart; a boat glides where every other mode stalls. Each technology defines its own cost surface across the landscape, and the paths that emerge from each surface are distinct.

Roman roads were engineered for the cart — broad, graded, paved — tolerating no more than about 8–10% grade. Mule tracks wound steeper. Aqueducts demanded near- perfect level. Waterways ignored slope entirely, paying instead for portage at every division.

Select a transport mode and observe how the network reconfigures. Cart routes cluster in valleys; pedestrian routes cut directly across ridges; watercraft abandon the land entirely.

III.4

Intermodal Pathfinding

No single mode dominates every environment. The most efficient journeys in pre-industrial Rome combined boat along the Tiber, cart along the Via Appia, and foot for the last mile into the hills. But changing modes is expensive: cargo must be unloaded, repacked, transferred, and reloaded. Animals must be exchanged. Vessels must find harbour.

Each modal transition carries a fixed penalty that represents this friction — the toll of the warehouse, the wait at the dock, the cost of the carter's guild. When that penalty is low, routes fragment into many short modal segments; when high, travellers commit to a single mode for the whole journey even at the cost of efficiency.

The simulation computes the cheapest combined route across two modes (land and water), penalising every shore crossing by the transition cost. Red cells mark where crossings concentrate into natural terminals — the embryo of a port.

// Intermodal edge cost
function edgeCost(i, d):
  base = movementCost(i, d, currentMode(i))

  if isWater[i] ≠ isWater[nbr]:
    base += TRANSITION_PENALTY   // modal switch cost

  return base

III.5

Path Dependency

A path used once is easier to use again. Vegetation is trampled; the surface compacts; the route becomes known. With investment, a track becomes a road: graded, drained, paved. Each improvement further concentrates traffic, which justifies further improvement. The result is a self-reinforcing network — a small number of dominant corridors emerge from what began as a uniform probability field.

This is path dependency: the cost of movement through a given edge decreases as a function of how many times it has been traversed. The reduction is multiplicative and asymptotic — a well-worn road eventually costs half what a virgin path does, but never zero. The shape of that decay curve determines whether the network consolidates quickly into a few highways or spreads evenly across the terrain.

Run the simulation with path dependency off first, then on. The contrast reveals how much of Rome's road pattern is terrain, and how much is history.

// Path-dependent edge cost
function edgeCost(i, d):
  base = nbrBase[i, d]          // static terrain cost
  tc   = nbrTc[i, d]            // travel count on this edge

  factor = 0.5 + 0.5^(tc + 1)
  // tc=0 → 1.0  (full cost, virgin ground)
  // tc=1 → 0.75 (worn track)
  // tc=4 → 0.53 (established road)
  // tc→∞ → 0.50 (paved highway, minimum)

  return base × factor

// Shore crossing penalty decays independently to zero:
shoreCost(tc) = P_TRANSITION × 0.5^tc
